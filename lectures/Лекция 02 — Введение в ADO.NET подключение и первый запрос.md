# Лекция 2 Введение в ADO.NET подключение и первый запрос

**Дисциплина:** ADO.NET  
**Продолжительность:** 2 академических часа — 90 минут

Программа учебного журнала должна обратиться к конкретному серверу, открыть нужную базу и получить результат. На этом занятии мы подготовим учебную таблицу, разберём строку подключения и напишем консольное приложение, которое выводит количество студентов.

После занятия вы сможете установить провайдер, открыть `SqlConnection`, выполнить `SqlCommand`, получить одно значение и объяснить, как освобождаются ресурсы при успешном выполнении и при ошибке.

## Подготовка среды

Для практики нужен именно работающий движок SQL Server. SSMS — программа управления сервером; её наличие само по себе не означает, что SQL Server установлен.

В этой лекции используем **SQL Server Express LocalDB** — локальный вариант SQL Server для разработки под Windows. Его можно установить через Visual Studio Installer как отдельный компонент. Стандартное имя автоматического экземпляра — `(localdb)\MSSQLLocalDB`. [SQL Server Express LocalDB](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/sql-server-express-localdb).

Перед работой:

1. Выполните `dotnet --info` в терминале и убедитесь, что доступен SDK.
2. Проверьте LocalDB командой `sqllocaldb info`.
3. Подключитесь к `(localdb)\MSSQLLocalDB` из SSMS или Visual Studio с аутентификацией Windows.

Если в кабинете используется общий SQL Server, преподаватель сообщает имя экземпляра и разрешённую базу. В таком случае не создавайте новую базу на общем сервере без согласования: используйте выделенную учебную базу, а в строке подключения замените сервер и имя базы.

## Создание базы и таблицы

Следующий скрипт предназначен для **новой локальной учебной базы**. Выполните его один раз в SSMS либо редакторе SQL, подключённом к вашему LocalDB. Здесь нет команд удаления существующих данных.

```sql
USE master;
GO

CREATE DATABASE CollegeAdo;
GO

USE CollegeAdo;
GO

CREATE TABLE dbo.Students
(
    StudentId int IDENTITY(1, 1) NOT NULL
        CONSTRAINT PK_Students PRIMARY KEY,
    FullName nvarchar(100) NOT NULL,
    GroupName nvarchar(20) NOT NULL,
    Email nvarchar(150) NULL
);
GO

INSERT INTO dbo.Students (FullName, GroupName, Email)
VALUES
    (N'Анна Иванова', N'ИСП-21', N'anna@example.com'),
    (N'Борис Петров', N'ИСП-21', NULL),
    (N'Вера Соколова', N'ИСП-22', N'vera@example.com');
GO

SELECT StudentId, FullName, GroupName, Email
FROM dbo.Students
ORDER BY StudentId;
```

`IDENTITY(1, 1)` задаёт автоматическую генерацию идентификаторов с начальным значением 1 и шагом 1. При вставке перечислены только остальные поля. Префикс `N` используется для строковых литералов Unicode, а `NULL` в почте Бориса означает отсутствие значения.

Ожидается три записи с идентификаторами 1, 2 и 3. Повторный запуск всего скрипта приведёт к ошибке создания существующей базы или таблицы, а повтор одного блока `INSERT` добавит дубликаты учебных данных. Для следующих занятий используйте уже подготовленную базу.

`GO` — разделитель пакетов в инструментах SQL Server. Его не нужно включать в текст обычного `SqlCommand`; из C# мы будем отправлять отдельные SQL-команды. [Разделитель GO](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/sql-server-utilities-statements-go).

## Создание проекта и установка провайдера

Создайте проект в выбранной папке для учебных работ. Команды выполняются последовательно:

```powershell
dotnet new console -n AdoNetLesson02
Set-Location AdoNetLesson02

```

Пакет предоставляет реализацию ADO.NET для SQL Server. В коде будем импортировать пространство имён `Microsoft.Data.SqlClient`. Установка пакета и директива `using` решают разные задачи: первая добавляет зависимость, вторая позволяет обращаться к типам по коротким именам. [Установка и пространство имён SqlClient](https://learn.microsoft.com/en-us/sql/connect/ado-net/introduction-microsoft-data-sqlclient-namespace).

## Строка подключения

**Строка подключения** состоит из пар `ключ=значение`, разделённых точками с запятой. Для локального примера:

```csharp
string connectionString =
    @"Server=(localdb)\MSSQLLocalDB;Database=CollegeAdo;Integrated Security=True;Encrypt=False;";
```

| Параметр | Значение в примере | Назначение |
| --- | --- | --- |
| `Server` | `(localdb)\MSSQLLocalDB` | Экземпляр SQL Server |
| `Database` | `CollegeAdo` | База данных |
| `Integrated Security` | `True` | Аутентификация Windows |
| `Encrypt` | `False` | Явная настройка для этого локального учебного примера |

При Windows-аутентификации используются права учётной записи, от которой запущен процесс. LocalDB работает локально; эту учебную строку не следует переносить на удалённый сервер. Для обычного сетевого SQL Server используйте настройки сервера, шифрование и проверку сертификата, например `Encrypt=True;TrustServerCertificate=False`, с корректным серверным сертификатом. [Строки подключения SqlClient](https://learn.microsoft.com/en-us/sql/connect/ado-net/connection-strings).

Символ `@` перед строкой — синтаксис C# для дословного строкового литерала: обратная косая черта не начинает escape-последовательность. Обычная строка с тем же адресом выглядела бы как `"Server=(localdb)\\MSSQLLocalDB;..."`.

В примере нет пароля. Если сервер требует SQL-аутентификацию, секреты не следует записывать в исходный код или публиковать вместе с проектом. Отдельные способы конфигурации будут рассмотрены в следующих темах курса.

## Полная программа первого запроса

Замените содержимое `Program.cs` следующим кодом. Это самостоятельная программа с инструкциями верхнего уровня; не помещайте её внутрь другого `Main`.

```csharp
using System;
using Microsoft.Data.SqlClient;

string connectionString =
    @"Server=(localdb)\MSSQLLocalDB;Database=CollegeAdo;Integrated Security=True;Encrypt=False;";

try
{
    using var connection = new SqlConnection(connectionString);
    using var command = new SqlCommand(
        "SELECT COUNT(*) FROM dbo.Students;",
        connection);

    connection.Open();
    Console.WriteLine($"Подключено к базе {connection.Database}");

    object? result = command.ExecuteScalar();

    if (result is int count)
    {
        Console.WriteLine($"Количество студентов: {count}");
    }
    else
    {
        throw new InvalidOperationException(
            "Запрос COUNT(*) вернул неожиданный результат.");
    }
}
catch (SqlException ex)
{
    Console.Error.WriteLine($"Ошибка SQL Server {ex.Number}: {ex.Message}");
    Environment.ExitCode = 1;
}
catch (InvalidOperationException ex)
{
    Console.Error.WriteLine($"Ошибка операции: {ex.Message}");
    Environment.ExitCode = 1;
}
```

Запуск:

```powershell
dotnet run
```

Если база создана приведённым скриптом и затем не изменялась, ожидается:

```text
Подключено к базе CollegeAdo
Количество студентов: 3
```

## Разбор выполнения программы

Конструктор `SqlConnection` создаёт объект с настройками, но подключение открывается вызовом `Open()`. Команда может быть подготовлена заранее; для её выполнения подключение должно быть открыто.

`ExecuteScalar()` возвращает первый столбец первой строки результата как `object`. Остальные строки и столбцы не используются. Если результат вообще не содержит строк, метод возвращает `null`. [Справочник ExecuteScalar](https://learn.microsoft.com/en-us/dotnet/api/microsoft.data.sqlclient.sqlcommand.executescalar).

В нашем запросе `COUNT(*)` без `GROUP BY` возвращает одну строку: число записей. Для пустой таблицы это будет `0`, а не отсутствие результата. Проверка `result is int count` одновременно проверяет тип и создаёт переменную `count`.

Различайте три ситуации:

| Ситуация | Смысл | Представление |
| --- | --- | --- |
| `COUNT(*)` вернул ноль | Строк в таблице нет | Значение `0` |
| Поиск не вернул строку | Искомая запись отсутствует | `null` от `ExecuteScalar()` |
| Строка есть, но поле SQL равно `NULL` | Значение поля не указано | `DBNull.Value` |

SQL `NULL` и C# `null` относятся к разным уровням. Для передачи SQL `NULL` через параметр применяется `DBNull.Value`. Подробно обработаем необязательную почту при чтении строк в лекции 3. [Типы и значения параметров](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/configuring-parameters-and-parameter-data-types).

## Освобождение ресурсов через using

Объявление `using var` гарантирует вызов `Dispose()` при выходе из текущей области видимости, в том числе при исключении. Здесь область — блок `try`. Объекты освобождаются в обратном порядке: сначала команда, затем подключение. [Объявление using в C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/statements/using).

Нельзя полагаться только на строку `connection.Close()` в самом конце успешного пути: при ошибке выполнение может до неё не дойти. `using` связывает время жизни ресурса с блоком кода и делает освобождение предсказуемым.

В SqlClient по умолчанию используется **пул подключений**. После освобождения объекта пригодное физическое подключение обычно возвращается в пул и может быть использовано повторно. Поэтому создавайте объект на время операции и освобождайте его после работы; держать одно глобальное соединение открытым постоянно не требуется. [Пул подключений SQL Server](https://learn.microsoft.com/en-us/sql/connect/ado-net/sql-server-connection-pooling).

## Диагностика ошибок

Ошибка обращения к данным может возникнуть при открытии соединения или выполнении команды. Начните с определения этапа: проблема доступа к серверу и неправильное имя столбца требуют разных исправлений.

| Признак | Что проверить |
| --- | --- |
| Тип `SqlConnection` не найден | Установлен ли пакет, указано ли пространство имён |
| Экземпляр сервера не найден | Установлен ли LocalDB, совпадает ли `Server` |
| База недоступна | Создана ли `CollegeAdo` именно в этом экземпляре |
| Ошибка входа | Под какой учётной записью работает программа и есть ли права |
| Объект `Students` не найден | Выбрана ли нужная база, создана ли `dbo.Students` |
| Ошибка синтаксиса SQL | Правильно ли записан текст команды |

Успешное подключение в SSMS полезно для проверки, но убедитесь, что приложение использует тот же сервер, ту же базу и подходящую учётную запись. Не исправляйте ошибку сертификата удалённого сервера случайным отключением проверки: сначала проверьте его настройки подключения.

## Самостоятельная работа

1. Запустите исходную программу и получите значение `3` на исходных данных.
2. Замените запрос на `SELECT COUNT(*) FROM dbo.Students WHERE Email IS NULL;`. Ожидается `1`.
3. Замените его на `SELECT COUNT(*) FROM dbo.Students WHERE GroupName = N'ИСП-21';`. Ожидается `2`. В этом упражнении значение фиксировано в коде; пользовательский ввод в следующей лекции передадим через параметр.
4. Временно измените имя таблицы на несуществующее. Определите, на каком вызове возникает ошибка, затем восстановите программу.
5. Объясните, почему ресурсы будут освобождены и после исключения.

**Критерий выполнения:** приложение запускается, запросы дают ожидаемые числа, ошибка выводится осмысленно, подключение и команда объявлены через `using`.

## Контрольные вопросы

1. Чем создание `SqlConnection` отличается от вызова `Open()`?
2. Какая часть строки подключения выбирает базу?
3. Зачем устанавливать пакет, если в коде уже написан `using`?
4. Что возвращает `ExecuteScalar`, когда строк нет?
5. Чем `0`, `null` и `DBNull.Value` отличаются в этих примерах?
6. В какой момент освобождается объект при `using var`?

**Краткие ответы:** конструктор создаёт объект, `Open` открывает подключение; базу выбирает `Database`; директива не устанавливает зависимость; без строк возвращается `null`; ноль — число, `null` — отсутствие результата, `DBNull.Value` — SQL `NULL`; освобождение происходит при выходе из области видимости.
