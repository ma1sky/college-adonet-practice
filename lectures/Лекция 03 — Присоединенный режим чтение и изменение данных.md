# Лекция 3 Присоединенный режим чтение и изменение данных

**Дисциплина:** ADO.NET  
**Продолжительность:** 2 академических часа — 90 минут  
**Предварительные знания:** лекции 1 и 2; `SELECT`, `INSERT`, `UPDATE`, `DELETE`; методы и цикл `while` в C#.  
**Среда:** проект C# с пакетом `Microsoft.Data.SqlClient`, локальная база `CollegeAdo` и таблица `dbo.Students` из лекции 2.

Подсчёт студентов возвращает одно число. Для журнала также нужны список записей, поиск по группе и изменение данных. В присоединённом режиме программа выполняет команду при открытом подключении и читает результат до освобождения ресурсов.

После занятия вы сможете прочитать строки через `SqlDataReader`, передать значения через параметры, обработать необязательное поле и выполнить основные операции CRUD. Транзакции, хранимые процедуры и более сложные сценарии присоединённого доступа остаются для следующих занятий.

## Время жизни подключения

Типичный путь операции:

```text
Создать подключение и команду
             ↓
Добавить параметры
             ↓
Открыть подключение
             ↓
Выполнить команду
             ↓
Прочитать результат
             ↓
Освободить reader, команду и подключение
```

При работе с `DataReader` подключение остаётся открытым на протяжении чтения. Reader предоставляет последовательный доступ вперёд и не предназначен для редактирования строк. Изменение выполняется отдельной командой. [Чтение через DataReader](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/retrieving-data-using-a-datareader).

Если нужны данные для длительного показа на экране, прочитайте их в собственные объекты или таблицу в памяти, затем освободите подключение. Ожидание ввода пользователя не должно продлевать время работы reader.

## Чтение через SqlDataReader

После `ExecuteReader()` reader находится перед первой строкой. `Read()` переводит его к следующей строке и возвращает `true`, если строка существует. Когда данные заканчиваются, возвращается `false`.

Ниже фрагмент, который выполняется внутри метода с уже открытым `connection`:

```csharp
using var command = new SqlCommand(
    "SELECT StudentId, FullName FROM dbo.Students ORDER BY StudentId;",
    connection);
using var reader = command.ExecuteReader();

while (reader.Read())
{
    int id = reader.GetInt32(0);
    string fullName = reader.GetString(1);
    Console.WriteLine($"{id}: {fullName}");
}
```

Номера столбцов начинаются с нуля и соответствуют порядку в `SELECT`. Для более явно читаемого кода можно определить индекс по имени через `GetOrdinal("FullName")` один раз перед циклом. Не обращайтесь к значениям до первого успешного `Read()` или после его результата `false`.

`SELECT *` делает код зависимым от всех столбцов таблицы. В учебных программах перечисляем поля явно: так видно, какие значения читаются и в каком порядке.

## Типы данных и SQL NULL

Типизированный метод чтения должен соответствовать типу столбца. Для нашей таблицы используются следующие соответствия. [Типы SQL Server и .NET](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/sql-server-data-type-mappings).

| Тип SQL Server | Тип C# | Метод чтения |
| --- | --- | --- |
| `int` | `int` | `GetInt32()` |
| `bigint` | `long` | `GetInt64()` |
| `nvarchar` | `string` | `GetString()` |
| `bit` | `bool` | `GetBoolean()` |
| `decimal` | `decimal` | `GetDecimal()` |
| `datetime2` | `DateTime` | `GetDateTime()` |

Для необязательной почты сначала проверяем `IsDBNull`:

```csharp
int emailIndex = reader.GetOrdinal("Email");
string? email = reader.IsDBNull(emailIndex)
    ? null
    : reader.GetString(emailIndex);
```

В этом фрагменте `null` уже относится к переменной C#, а SQL `NULL` распознаётся методом `IsDBNull`. Пустая строка `""` и отсутствие значения имеют разный смысл; не заменяйте одно другим без решения, принятого для приложения.

## Передача параметров

Пусть пользователь выбирает группу. Текст запроса остаётся постоянным, меняется только значение:

```csharp
using var command = new SqlCommand(
    "SELECT StudentId, FullName FROM dbo.Students WHERE GroupName = @group;",
    connection);
command.Parameters.Add("@group", SqlDbType.NVarChar, 20).Value = groupName;
```

Для этого фрагмента требуется `using System.Data;`. Имя `@group` в SQL совпадает с именем параметра. Значение не заключают в кавычки внутри запроса: запись `WHERE GroupName = '@group'` искала бы буквальный текст `@group`.

Параметры передают значения отдельно от текста команды. В примерах явно указываем тип `SqlDbType` и размер строкового поля, соответствующие таблице. [Настройка параметров](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/configuring-parameters-and-parameter-data-types).

Не собирайте запрос из фрагментов пользовательского ввода:

```csharp
// Небезопасный способ, приведён только для разбора ошибки.
string sql = "SELECT StudentId FROM dbo.Students WHERE FullName = '"
    + enteredName + "';";
```

Такой код смешивает данные и SQL. Параметр позволяет корректно передать и имя с апострофом, и другую произвольную строку. Он не подставляет имя таблицы или направление сортировки: такие части SQL выбирают из заранее заданных допустимых вариантов.

## Выбор метода для CRUD

**CRUD** — четыре основные операции: Create, Read, Update и Delete, то есть создание, чтение, изменение и удаление.

| Действие | Что нужно приложению | Метод в нашем примере |
| --- | --- | --- |
| Найти студентов группы | Строки | `ExecuteReader()` |
| Добавить студента | Новый идентификатор | `ExecuteScalar()` с `OUTPUT INSERTED.StudentId` |
| Изменить группу | Количество изменённых строк | `ExecuteNonQuery()` |
| Удалить студента | Количество удалённых строк | `ExecuteNonQuery()` |

`ExecuteNonQuery()` возвращает число затронутых строк для обычных `INSERT`, `UPDATE` и `DELETE`. Значение не является идентификатором и не означает просто «успех» или «ошибка». На подсчёт могут влиять триггеры и `SET NOCOUNT ON`; некоторые команды возвращают `-1`. В нашей учебной таблице триггеров нет, `NOCOUNT` не включаем. [Справочник ExecuteNonQuery](https://learn.microsoft.com/en-us/dotnet/api/microsoft.data.sqlclient.sqlcommand.executenonquery).

## Полная программа работы со студентами

Создайте новый консольный проект `AdoNetLesson03`, установите пакет командой `dotnet add package Microsoft.Data.SqlClient` и замените весь `Program.cs` следующим кодом. Базу повторно создавать не нужно.

Программа сначала показывает группу ИСП-21, затем добавляет **отдельную демонстрационную запись**, меняет её группу, показывает результат и удаляет именно эту запись по полученному идентификатору. Если выполнение прервётся после вставки, демонстрационная запись может остаться в базе: несколько команд пока не объединены в транзакцию.

```csharp
using System;
using System.Data;
using Microsoft.Data.SqlClient;

string connectionString =
    @"Server=(localdb)\MSSQLLocalDB;Database=CollegeAdo;Integrated Security=True;Encrypt=False;";

try
{
    Console.WriteLine("Студенты ИСП-21 до добавления:");
    ShowStudents(connectionString, "ИСП-21");

    int newId = AddStudent(
        connectionString, "Учебный студент", "ИСП-21", null);
    Console.WriteLine($"Добавлен студент, ID = {newId}");

    int updated = ChangeGroup(connectionString, newId, "ИСП-22");
    Console.WriteLine($"Изменено строк: {updated}");

    Console.WriteLine("Студенты ИСП-22 после изменения:");
    ShowStudents(connectionString, "ИСП-22");

    int deleted = DeleteStudent(connectionString, newId);
    Console.WriteLine($"Удалено строк: {deleted}");
}
catch (SqlException ex)
{
    Console.Error.WriteLine($"Ошибка SQL Server {ex.Number}: {ex.Message}");
    Environment.ExitCode = 1;
}
catch (InvalidOperationException ex)
{
    Console.Error.WriteLine($"Ошибка операции: {ex.Message}");
    Environment.ExitCode = 1;
}

static void ShowStudents(string connectionString, string groupName)
{
    using var connection = new SqlConnection(connectionString);
    using var command = new SqlCommand(
        "SELECT StudentId, FullName, GroupName, Email " +
        "FROM dbo.Students WHERE GroupName = @group " +
        "ORDER BY StudentId;",
        connection);
    command.Parameters.Add("@group", SqlDbType.NVarChar, 20).Value = groupName;

    connection.Open();
    using var reader = command.ExecuteReader();

    int idIndex = reader.GetOrdinal("StudentId");
    int nameIndex = reader.GetOrdinal("FullName");
    int groupIndex = reader.GetOrdinal("GroupName");
    int emailIndex = reader.GetOrdinal("Email");
    bool found = false;

    while (reader.Read())
    {
        found = true;
        int id = reader.GetInt32(idIndex);
        string name = reader.GetString(nameIndex);
        string group = reader.GetString(groupIndex);
        string email = reader.IsDBNull(emailIndex)
            ? "не указана"
            : reader.GetString(emailIndex);

        Console.WriteLine($"{id}: {name}, {group}, почта: {email}");
    }

    if (!found)
    {
        Console.WriteLine("Студенты не найдены.");
    }
}

static int AddStudent(
    string connectionString, string fullName, string groupName, string? email)
{
    using var connection = new SqlConnection(connectionString);
    using var command = new SqlCommand(
        "INSERT INTO dbo.Students (FullName, GroupName, Email) " +
        "OUTPUT INSERTED.StudentId " +
        "VALUES (@name, @group, @email);",
        connection);
    command.Parameters.Add("@name", SqlDbType.NVarChar, 100).Value = fullName;
    command.Parameters.Add("@group", SqlDbType.NVarChar, 20).Value = groupName;
    command.Parameters.Add("@email", SqlDbType.NVarChar, 150).Value =
        email is null ? DBNull.Value : (object)email;

    connection.Open();
    object? result = command.ExecuteScalar();

    if (result is int id)
    {
        return id;
    }

    throw new InvalidOperationException("Не получен ID нового студента.");
}

static int ChangeGroup(string connectionString, int studentId, string groupName)
{
    using var connection = new SqlConnection(connectionString);
    using var command = new SqlCommand(
        "UPDATE dbo.Students SET GroupName = @group WHERE StudentId = @id;",
        connection);
    command.Parameters.Add("@group", SqlDbType.NVarChar, 20).Value = groupName;
    command.Parameters.Add("@id", SqlDbType.Int).Value = studentId;

    connection.Open();
    return command.ExecuteNonQuery();
}

static int DeleteStudent(string connectionString, int studentId)
{
    using var connection = new SqlConnection(connectionString);
    using var command = new SqlCommand(
        "DELETE FROM dbo.Students WHERE StudentId = @id;",
        connection);
    command.Parameters.Add("@id", SqlDbType.Int).Value = studentId;

    connection.Open();
    return command.ExecuteNonQuery();
}
```

Запустите проект командой `dotnet run`. При исходных трёх строках и первом запуске ожидается:

```text
Студенты ИСП-21 до добавления:
1: Анна Иванова, ИСП-21, почта: anna@example.com
2: Борис Петров, ИСП-21, почта: не указана
Добавлен студент, ID = 4
Изменено строк: 1
Студенты ИСП-22 после изменения:
3: Вера Соколова, ИСП-22, почта: vera@example.com
4: Учебный студент, ИСП-22, почта: не указана
Удалено строк: 1
```

Идентификатор демонстрационной записи на следующих запусках может отличаться. Удаление строки не означает повторное использование её номера. Программа берёт фактический ID из результата `INSERT`, поэтому не зависит от предположения, что новый номер обязательно равен 4.

## Разбор решений в программе

Каждый метод открывает подключение только на время своей операции. В `ShowStudents` reader освобождается первым, затем команда и подключение. Вызывающий код получает уже завершённый вывод, а не reader с закрытым соединением.

В `AddStudent` предложение `OUTPUT INSERTED.StudentId` возвращает идентификатор вставленной строки. Поэтому используется `ExecuteScalar`, хотя сама операция — вставка. При передаче отсутствующей почты параметр получает `DBNull.Value`. [Предложение OUTPUT](https://learn.microsoft.com/en-us/sql/t-sql/queries/output-clause-transact-sql).

`ChangeGroup` и `DeleteStudent` ограничивают операцию условием `WHERE StudentId = @id`. Если запись с таким ID отсутствует, результат в нашем примере будет `0`: это допустимый исход поиска, а не исключение. Первичный ключ гарантирует, что условию соответствует не более одной строки.

В тексте SQL несколько постоянных строк соединены оператором `+` только для удобства оформления кода. Значения имени, группы, почты и идентификатора передаются через параметры.

Методы предполагают заранее подготовленные значения. В приложении с вводом пользователя дополнительно проверьте, что имя и группа не пусты, длины укладываются в 100 и 20 символов, а почта — в 150. Параметры решают задачу передачи данных, но не заменяют прикладную проверку значений.

## Ошибки присоединённого доступа

| Ошибка | Причина | Исправление |
| --- | --- | --- |
| Чтение до `Read()` | Текущая строка ещё не выбрана | Читать значения только после `Read() == true` |
| `GetString` для `NULL` | Значение отсутствует | Сначала вызвать `IsDBNull` |
| `GetInt32` для `bigint` | Не соответствует тип | Использовать `GetInt64` |
| Новая команда при ещё открытом reader | Предыдущий результат не освобождён | Завершить чтение и освободить reader |
| Изменение всех студентов | Пропущено условие `WHERE` | Передавать ключ записи и ограничивать команду |
| Вместо ID используется результат `ExecuteNonQuery` | Перепутаны виды результатов | Получать ID через возвращающий его SQL и `ExecuteScalar` |

В рамках этой лекции не включаем Multiple Active Result Sets: работаем с одним активным reader на подключении. Это делает порядок операций и освобождение ресурсов явными.

## Самостоятельная работа

1. Добавьте метод `ShowStudentById(string connectionString, int studentId)`. Используйте параметр `@id`, `ExecuteReader` и условие `WHERE StudentId = @id`.
2. Проверьте метод на ID `1` и `-1`. Для исходных данных первый вызов выводит Анну Иванову, второй — сообщение об отсутствии записи.
3. Добавьте `ChangeEmail`, принимающий `string? email`. При `null` передавайте `DBNull.Value`. Изменяйте только демонстрационную запись и прочитайте её повторно до удаления.
4. Вызовите `ShowStudents` для отсутствующей группы. Программа должна вывести сообщение, а не обращаться к несуществующей строке.
5. Повторите удаление уже удалённой демонстрационной записи и объясните результат `0`.

**Критерий выполнения:** пользовательские значения передаются параметрами; SQL `NULL` обработан; изменения ограничены идентификатором; reader не используется вне своей области жизни; результат `0` объяснён корректно.

## Контрольные вопросы

1. Почему при чтении reader подключение должно оставаться открытым?
2. Что возвращает `Read()` и где reader находится сразу после создания?
3. Зачем проверять `IsDBNull` перед типизированным чтением?
4. Почему `ExecuteNonQuery()` нельзя считать способом получения ID?
5. Как программа получает идентификатор вставленной записи?
6. Что произойдёт с `UPDATE`, если убрать `WHERE`?
7. Почему после успешной вставки возможна незавершённая последовательность операций?

**Краткие ответы:** reader читает результат через действующее подключение; `Read` сообщает о наличии очередной строки, исходная позиция — перед первой; SQL `NULL` нельзя читать как обычную строку; `ExecuteNonQuery` возвращает число затронутых строк; ID возвращает `OUTPUT INSERTED.StudentId`; без `WHERE` изменение затронет все строки таблицы; команды выполняются отдельно, без общей транзакции.
