# Лекция 1 Введение в ADO.NET архитектура и основные понятия

**Дисциплина:** ADO.NET  
**Продолжительность:** 2 академических часа — 90 минут  
**Предварительные знания:** основы C#, классы, методы, коллекции; таблицы, первичные ключи и простой `SELECT`.  
**Среда курса:** C#, .NET, SQL Server и провайдер `Microsoft.Data.SqlClient`.

Приложение учебного журнала должно сохранять студентов между запусками, находить их по группе и показывать актуальные сведения нескольким пользователям. Список объектов в памяти решает только часть задачи: после завершения программы он исчезает. Для постоянного хранения будем использовать базу данных, а для обращения к ней из C# — ADO.NET.

После занятия вы сможете объяснить роль ADO.NET, различить обязанности приложения и СУБД, назвать основные объекты доступа к данным и выбрать подходящий режим работы. Это первая из двух вводных лекций; на следующем занятии вы создадите подключение и выполните первый запрос.

## Зачем приложению доступ к базе данных

Представим два действия пользователя: открыть список группы и добавить нового студента. В первом случае программа получает данные; во втором изменяет хранилище. Оба действия проходят через границу между процессом приложения и СУБД.

**База данных** хранит организованные данные. **Система управления базами данных**, или СУБД, принимает запросы, проверяет права, выполняет операции и обеспечивает ограничения целостности. В нашем примере СУБД — SQL Server.

Приложение отвечает за взаимодействие с пользователем и свою прикладную логику. SQL Server отвечает за выполнение SQL и хранение таблиц. Поэтому проверка пустого имени в форме и ограничение `NOT NULL` в таблице дополняют друг друга: первая помогает пользователю, второе защищает данные при любом способе записи.

Связь компонентов можно представить так:

```text
Пользователь
    ↓ ввод и действия
Приложение на C#
    ↓ объекты ADO.NET и провайдер
SQL Server
    ↓ выполнение SQL
Таблицы базы CollegeAdo
```

Стрелки показывают путь запроса. Результат или сообщение об ошибке проходит обратно к приложению, которое решает, что показать пользователю.

## Что такое ADO.NET

**ADO.NET** — модель доступа к данным в .NET: набор типов и соглашений для подключения к источникам данных, выполнения команд и обработки результатов. Это позволяет, например, отправить SQL-запрос из программы на C# и прочитать строки ответа. [Обзор ADO.NET](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/ado-net-overview).

Не следует смешивать три уровня:

| Уровень | Назначение | Пример |
| --- | --- | --- |
| C# | Описывает поведение приложения | Цикл вывода студентов |
| ADO.NET и провайдер | Передают команды и предоставляют результаты программе | `SqlCommand`, `SqlDataReader` |
| SQL | Описывает операцию для СУБД | `SELECT FullName FROM dbo.Students` |

Строка SQL остаётся текстом для компилятора C#. Если написать `SELEKT`, приложение может успешно скомпилироваться, а ошибка обнаружится при выполнении команды сервером. Так возникают два разных вида ошибок: ошибка программы на C# и ошибка команды SQL.

## Провайдер данных

**Провайдер** реализует доступ к определённому источнику данных. Общие абстракции находятся в `System.Data.Common`; конкретный провайдер предоставляет классы для своего сервера. Для новых приложений с SQL Server Microsoft рекомендует пакет `Microsoft.Data.SqlClient`. [Провайдер Microsoft.Data.SqlClient](https://learn.microsoft.com/en-us/sql/connect/ado-net/introduction-microsoft-data-sqlclient-namespace).

| Общая абстракция | Реализация для SQL Server | Что представляет |
| --- | --- | --- |
| `DbConnection` | `SqlConnection` | Подключение |
| `DbCommand` | `SqlCommand` | Команду |
| `DbParameter` | `SqlParameter` | Значение параметра |
| `DbDataReader` | `SqlDataReader` | Последовательное чтение результата |
| `DbTransaction` | `SqlTransaction` | Транзакцию |

В старых проектах встречается `System.Data.SqlClient`. В примерах курса используем `Microsoft.Data.SqlClient`, поэтому пространства имён и пакет должны соответствовать друг другу. Похожие названия классов из разных пространств имён не делают их одним и тем же типом.

Общий интерфейс доступа не делает любой SQL переносимым. Например, особенности SQL Server в тексте команды сохраняются, даже если переменная объявлена как `DbCommand`.

## Основные объекты ADO.NET

**Connection** содержит настройки подключения и позволяет открыть соединение. **Command** хранит текст SQL или имя процедуры, ссылку на подключение и параметры. **DataReader** предоставляет поток строк для чтения вперёд. **DataAdapter** связывает источник данных с таблицами в памяти. [Провайдеры данных ADO.NET](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/data-providers).

Запрос «показать студентов группы» можно разложить на действия:

1. Создать `SqlConnection` с адресом сервера и именем базы.
2. Создать `SqlCommand` с запросом к таблице студентов.
3. Передать название группы через `SqlParameter`.
4. Открыть подключение и выполнить команду.
5. Получить `SqlDataReader` и последовательно прочитать строки.
6. Освободить reader, команду и подключение.

На этом занятии важно понять распределение обязанностей. Точный синтаксис этих действий разберём во второй и третьей лекциях.

## Присоединённый и отсоединённый режимы

В **присоединённом режиме** подключение открыто во время выполнения команды и чтения её результатов. Например, программа читает строки через `DataReader`, а после завершения освобождает ресурсы.

В **отсоединённом режиме** приложение получает данные в память и продолжает работать с ними без постоянно открытого подключения. В классической модели ADO.NET для этого применяются `DataTable` и `DataSet`; `DataAdapter` может загружать данные и передавать подготовленные изменения обратно. Само изменение ячейки в памяти ещё не означает изменение базы. [Архитектура ADO.NET](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/ado-net-architecture).

| Критерий | Присоединённый режим | Отсоединённый режим |
| --- | --- | --- |
| Работа с результатом | По мере чтения строк | Через загруженные таблицы в памяти |
| Подключение | Нужно при выполнении и чтении | Нужно при загрузке и сохранении |
| Типичный объект | `DataReader` | `DataTable`, `DataSet` |
| Объём хранимых в приложении данных | Можно обрабатывать строки последовательно | Зависит от объёма загруженной выборки |
| Учебная задача | Сразу вывести список группы | Редактировать загруженную таблицу |

Отсоединённый режим не отменяет подключение вообще: для обмена с сервером оно необходимо. Присоединённый режим, в свою очередь, не требует держать соединение открытым всё время работы приложения.

Предположим, пользователь открыл карточку и думает над исправлением имени пять минут. Организуем работу так: прочитаем карточку, закроем подключение, дадим пользователю отредактировать поля, а при сохранении выполним отдельный запрос. Удерживать соединение во время ожидания ввода не требуется.

## Какой результат возвращает команда

Для выбора способа выполнения сначала сформулируйте, что нужно получить: строки, одно значение или количество изменённых записей. [Выполнение команд ADO.NET](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/executing-a-command).

| Задача | SQL | Метод |
| --- | --- | --- |
| Показать список | `SELECT StudentId, FullName FROM dbo.Students` | `ExecuteReader()` |
| Узнать количество | `SELECT COUNT(*) FROM dbo.Students` | `ExecuteScalar()` |
| Изменить группу | `UPDATE dbo.Students SET GroupName = @group WHERE StudentId = @id` | `ExecuteNonQuery()` |

Метод выбирают по нужному результату. В третьей лекции мы увидим, что даже `INSERT` может возвращать одно значение — идентификатор созданной записи.

## Сквозной пример учебного журнала

Для первых занятий достаточно одной таблицы:

| Поле | Тип SQL Server | Смысл |
| --- | --- | --- |
| `StudentId` | `int`, первичный ключ, `IDENTITY` | Идентификатор студента |
| `FullName` | `nvarchar(100)`, `NOT NULL` | Полное имя |
| `GroupName` | `nvarchar(20)`, `NOT NULL` | Учебная группа |
| `Email` | `nvarchar(150)`, `NULL` | Необязательная почта |

Имя не подходит на роль идентификатора: в группе могут учиться однофамильцы. При изменении записи будем передавать `StudentId`, чтобы однозначно указать нужного студента.

Обсудите запрос:

```sql
SELECT StudentId, FullName, GroupName
FROM dbo.Students
WHERE GroupName = @group
ORDER BY FullName, StudentId;
```

`WHERE` ограничивает выборку, `ORDER BY` задаёт порядок вывода, `@group` обозначает параметр со значением группы. При работе из C# это значение добавляется в коллекцию параметров команды.

Параметры отделяют значения от текста SQL: введённая строка передаётся как данные. Это помогает защитить запрос от SQL-инъекции, возникающей при небезопасном включении ввода в текст команды. [Параметры команд](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/configuring-parameters-and-parameter-data-types).

## Частые заблуждения

| Утверждение | Уточнение |
| --- | --- |
| ADO.NET — это база данных | Это средства доступа к данным из .NET |
| `SqlConnection` уже содержит строки таблицы | Он представляет подключение; результат получают выполнением команды |
| SQL выполняется компилятором C# | Запрос обрабатывает СУБД после отправки команды |
| Изменение объекта всегда меняет базу | Для записи нужна соответствующая операция доступа к данным |
| Отсоединённый режим совсем не использует соединение | Обмен с сервером требует подключения |

## Контрольные вопросы

1. Какую задачу ADO.NET решает в программе учебного журнала?
2. Чем провайдер отличается от СУБД?
3. За что отвечают `Connection`, `Command` и `DataReader`?
4. Когда нужен `DataSet` и почему он не равен базе данных?
5. Как выбрать между `ExecuteReader`, `ExecuteScalar` и `ExecuteNonQuery`?
6. Почему при изменении студента лучше использовать идентификатор?

**Краткие ответы:** ADO.NET обеспечивает доступ из приложения к данным; провайдер реализует взаимодействие с источником, а СУБД выполняет запросы и хранит данные; подключение открывает доступ, команда описывает операцию, reader читает результат; `DataSet` хранит таблицы в памяти; метод выбирают по форме результата; идентификатор однозначно указывает запись.
