# SQL Server и ADO.NET в GitHub Codespaces

Пошаговая инструкция для преподавателя и студентов с обычными личными аккаунтами GitHub Free. На компьютере нужны браузер и интернет. SQL Server, .NET SDK, провайдер ADO.NET и редактор запускаются в Codespaces.

Вместе с инструкцией используется архив **adonet-codespaces-starter.zip**. Он содержит готовые файлы учебного репозитория: конфигурацию контейнеров, проект C#, подготовку базы и проверочный SQL. Преподаватель один раз загружает их в GitHub, а студенты создают собственные копии.

**Что получится:** у каждого студента отдельное окружение с SQL Server 2022 Developer, .NET 10 и `Microsoft.Data.SqlClient 7.1.0`. Практика работает с настоящим SQL Server. Azure-аккаунт, подписка Azure и установленный на компьютере Docker не требуются. Codespaces создаёт облачную среду по конфигурации репозитория. [Конфигурация Codespaces](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/introduction-to-dev-containers).

В проекте зафиксирована версия провайдера для одинаковой подготовки группы. Образы SDK публикует Microsoft, пакет провайдера доступен в NuGet. [Образ .NET SDK](https://hub.docker.com/r/microsoft/dotnet-sdk/), [Microsoft.Data.SqlClient 7.1.0](https://www.nuget.org/packages/Microsoft.Data.SqlClient/7.1.0).

## Как устроено окружение

```text
Браузер студента
    ↓
Его собственный GitHub Codespace
    ├── app  .NET SDK и программа C#
    └── db   SQL Server 2022 и база CollegeAdo
                  ↑
             Docker volume sql-data
```

Приложение подключается к серверу по адресу `db,1433`: `db` — имя сервиса в Docker Compose. Это адрес внутри окружения, а не публичный адрес для браузера.

В конфигурации используется Developer Edition для учебной разработки. Контейнеру передаётся `ACCEPT_EULA=Y`: перед использованием преподавателю следует ознакомиться с условиями лицензии SQL Server. Такой подход к запуску описан в официальной документации Microsoft. [SQL Server в контейнере](https://learn.microsoft.com/en-us/sql/linux/install-upgrade/quickstart-install-docker?view=sql-server-ver17).

## Бесплатные лимиты

На дату проверки 9 ноября 2026 года GitHub Free для личного аккаунта включает:

| Ресурс | Квота в месяц |
| --- | --- |
| Вычисления | 120 ядро-часов |
| Хранение | 15 ГБ·месяц |

У двухъядерной машины коэффициент расхода равен 2: теоретический предел — 60 часов работы за месяц. У четырёхъядерной — 30 часов. Например, 8 занятий по 90 минут на двухъядерной машине расходуют примерно 24 ядро-часа без учёта запуска, подготовки и простоя.

**Это два независимых ограничения.** Образы контейнеров, база и файлы занимают место; предел хранения может закончиться раньше вычислительного. 15 ГБ·месяц — накопленное использование хранилища за месяц, а не размер диска машины. При отсутствии способа оплаты GitHub блокирует дальнейшее использование после исчерпания квоты. Если карта уже привязана, отдельно проверьте бюджеты и условия остановки расходов. [Квоты и учёт Codespaces](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces).

Каждый студент создаёт Codespace под своим личным аккаунтом. Для этой схемы не включайте оплату окружений за счёт организации. Машину с 2 ядрами используем как начальную конфигурацию; перед занятием преподаватель проверяет, что её хватает для конкретной работы. При переходе на 4 ядра бесплатное время расходуется быстрее.

## Часть 1 Подготовка репозитория преподавателем

### Шаг 1 Распакуйте архив

Распакуйте `adonet-codespaces-starter.zip` средствами операционной системы. Внутри должны находиться:

```text
.devcontainer/
    devcontainer.json
    docker-compose.yml
    Dockerfile
    setup.sh
practice/
    Practice.csproj
    Program.cs
    LabDb.cs
sql/
    01-init.sql
    02-check.sql
.gitignore
.gitattributes
README.md
ИНСТРУКЦИЯ.md
```

Папка `.devcontainer` начинается с точки. Сохраните её имя без изменений. Важен именно такой путь: `.devcontainer/devcontainer.json` в корне репозитория.

### Шаг 2 Создайте репозиторий

1. Войдите в свой аккаунт GitHub.
2. Нажмите **New repository**.
3. Укажите имя, например `college-adonet-practice`.
4. Владельцем выберите свой личный аккаунт.
5. Для доступного группе учебного шаблона выберите **Public**. В нём должны быть только учебные данные.
6. Не добавляйте начальные README и `.gitignore`: они уже есть в архиве.
7. Нажмите **Create repository**.

### Шаг 3 Загрузите файлы

1. На странице пустого репозитория нажмите **uploading an existing file**. Для уже созданного непустого репозитория путь — **Add file → Upload files**.
2. Перетащите **содержимое** распакованной папки: `.devcontainer`, `practice`, `sql`, README и остальные файлы. Сам ZIP загружать вместо файлов не нужно.
3. Введите сообщение коммита, например `Add ADO.NET classroom environment`.
4. Сохраните изменения в ветку `main`.
5. Откройте `.devcontainer` на GitHub и убедитесь, что все четыре файла видны.

Правильно: `college-adonet-practice/.devcontainer/devcontainer.json`. Неправильно: `college-adonet-practice/adonet-codespaces-starter/.devcontainer/devcontainer.json`. Во втором случае Codespaces не найдёт конфигурацию автоматически.

Если перетаскивание папки с точкой не сработало, используйте **Add file → Create new file** и создайте нужные файлы по полным путям, например `.devcontainer/devcontainer.json`, скопировав содержимое из архива.

### Шаг 4 Сделайте репозиторий шаблоном

1. Откройте **Settings → General** своего репозитория.
2. Включите **Template repository**.
3. Вернитесь на главную страницу и убедитесь, что доступна кнопка **Use this template**.

Студент сможет создать отдельный репозиторий с теми же файлами. Это удобно для сохранения и проверки индивидуальных работ. [Репозиторий из шаблона](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template).

### Шаг 5 Проверьте запуск на своём аккаунте

1. Откройте **Code → Codespaces**.
2. В меню рядом с кнопкой создания выберите **New with options**, если этот пункт доступен.
3. Выберите ветку `main`, конфигурацию **ADO.NET and SQL Server practice** и машину **2-core**.
4. Нажмите **Create codespace**.
5. Дождитесь окончания создания контейнеров и команды подготовки. При первом запуске загружаются образы и NuGet-пакеты, поэтому создание может занять несколько минут.

При создании окружения выполняется `postCreateCommand` из `devcontainer.json`. Не запускайте параллельно вторую подготовку базы, пока первая ещё работает. [Создание Codespace](https://docs.github.com/en/codespaces/developing-in-a-codespace/creating-a-codespace-for-a-repository).

В результате появится терминал с сообщениями:

```text
База CollegeAdo готова.
Environment ready. Run: dotnet run --project practice -- list
```

Если терминал не открыт, выберите **Terminal → New Terminal**. Все команды далее выполняются в терминале Codespaces из корня репозитория, где находятся папки `practice` и `sql`.

### Шаг 6 Проверьте ADO.NET и данные

Выполните по очереди:

```bash
dotnet --info
dotnet run --project practice -- count
dotnet run --project practice -- list
dotnet run --project practice -- list "ИСП-21"
dotnet run --project practice -- sql sql/02-check.sql
```

Ожидаемые результаты на новой базе:

- `dotnet --info` показывает установленный SDK .NET 10.
- `count` выводит `Количество студентов: 3`.
- `list` выводит Анну Иванову, Бориса Петрова и Веру Соколову.
- По группе ИСП-21 выводятся Анна и Борис, у Бориса почта обозначена как `не указана`.
- SQL-проверка показывает версию SQL Server, три строки студентов и `TransferCount`, равный `0`.

После проверки отправьте студентам ссылку на **репозиторий-шаблон**. Ссылка на ваше запущенное окружение им не нужна: каждый работает в собственном.

## Часть 2 Первый запуск студентом

### Шаг 1 Создайте свою копию

1. Войдите в свой личный бесплатный аккаунт GitHub.
2. Откройте ссылку преподавателя.
3. Нажмите **Use this template → Create a new repository**.
4. Владельцем выберите свой аккаунт.
5. Укажите имя, например `adonet-practice-ivanov`.
6. Выберите видимость, согласованную с преподавателем, и нажмите **Create repository**. Для приватной работы преподавателю понадобится отдельно предоставить доступ.

После создания адрес должен содержать ваш логин, а не логин преподавателя.

### Шаг 2 Откройте Codespaces

1. Уже в своём репозитории откройте **Code → Codespaces**.
2. Выберите создание с параметрами и машину **2-core**.
3. Создайте окружение и дождитесь сообщения `База CollegeAdo готова.`.
4. Откройте терминал и выполните:

```bash
dotnet run --project practice -- count
dotnet run --project practice -- list "ИСП-21"
```

Если получены число `3` и два студента, связка C# → ADO.NET → SQL Server работает.

### Шаг 3 Сделайте первую практику

1. Откройте файл `practice/Program.cs`.
2. Найдите обработку команды `list`: в ней есть `SqlConnection`, `SqlCommand`, параметр `@group`, `ExecuteReader` и цикл `Read`.
3. Выполните поиск для ИСП-22 и для отсутствующей группы:

```bash
dotnet run --project practice -- list "ИСП-22"
dotnet run --project practice -- list "НЕТ-00"
```

Ожидаются Вера Соколова в первом случае и сообщение `Студенты не найдены.` во втором.

Для самостоятельного SQL создайте файл `sql/my-query.sql`:

```sql
SELECT StudentId, FullName, GroupName
FROM dbo.Students
WHERE Email IS NULL;
```

Запустите его:

```bash
dotnet run --project practice -- sql sql/my-query.sql
```

На исходных данных выводится Борис Петров. Команда `sql` выполняет ваш файл через ADO.NET. Она поддерживает обычный `GO` на отдельной строке как учебный разделитель; `GO 5` с числом повторов не поддерживается.

## Часть 3 Работа с примерами четырёх лекций

В лекциях используется Windows LocalDB. В Codespaces работает Linux-контейнер SQL Server, поэтому адрес `(localdb)\MSSQLLocalDB` и Windows-аутентификация здесь не подходят.

Для выполнения примеров в готовом проекте:

1. Сохраните исходный `Program.cs` коммитом или скопируйте его содержимое в файл с расширением `.txt`.
2. Замените содержимое `practice/Program.cs` **одним** полным примером из нужной лекции.
3. Оставьте файл `practice/LabDb.cs` на месте.
4. Вместо строки подключения из лекции напишите:

```csharp
string connectionString = LabDb.ConnectionString;
```

5. Запустите программу:

```bash
dotnet run --project practice
```

Не добавляйте рядом второй `.cs` с инструкциями верхнего уровня: в одном проекте такой файл должен быть один. Сохранённая копия может иметь расширение `.txt` или находиться вне папки проекта.

После замены `Program.cs` команды `init`, `list`, `count` и `sql` больше не работают, если вы не сохранили их обработку. Для выполнения SQL тогда используйте расширение MSSQL либо восстановите исходный запускатель, предварительно сохранив свой код.

| Лекция | Что меняется для Codespaces |
| --- | --- |
| 1 Архитектура | Основные понятия и классы сохраняются |
| 2 Подключение | Используйте `LabDb.ConnectionString`; создание базы и вставка трёх студентов уже выполнены |
| 3 CRUD | Замените только получение строки подключения; остальная логика примера сохраняется |
| 4 Транзакции | Замените получение строки подключения; таблица `StudentTransfers` уже создана, повторный `CREATE TABLE` не нужен |

Инициализация создаёт таблицы только при их отсутствии. Повтор команды `init` не удаляет записи и не возвращает студентов в исходные группы. После успешного перевода в лекции 4 используйте фактическую текущую группу, как указано в самой лекции.

## Часть 4 Просмотр SQL через расширение MSSQL

Расширение `ms-mssql.mssql` указано в конфигурации и устанавливается в удалённое окружение. Оно позволяет выполнять SQL и смотреть результаты в браузерном VS Code. Терминальная команда `sql` выше остаётся запасным способом выполнения запросов.

1. Откройте палитру команд через **F1** или **Ctrl+Shift+P**.
2. Найдите **MS SQL: Connect** либо создание подключения в панели SQL Server.
3. Укажите параметры:

| Поле | Значение |
| --- | --- |
| Server | `db,1433` |
| Authentication | SQL Login |
| User name | `sa` |
| Password | `College_Lab_2026!Only` |
| Database | `CollegeAdo` |
| Encrypt | Включено |
| Trust server certificate | Включено для этого учебного контейнера |

4. Назовите подключение, например `CollegeAdo Codespaces`.
5. Откройте `sql/02-check.sql` и выполните запрос через команду расширения **Execute Query**.

Порядок создания подключения и выбор аутентификации описаны в [документации расширения MSSQL](https://learn.microsoft.com/en-us/sql/tools/visual-studio-code-extensions/mssql/mssql-database-connections?view=sql-server-ver17).

Названия полей могут немного отличаться между версиями расширения. Не пытайтесь открыть `db,1433` как веб-страницу: это адрес сервера для SQL-клиента.

Учебный пароль хранится в конфигурации репозитория и не является секретом. Он используется только для изолированных учебных баз. Порт 1433 не публикуется наружу: не добавляйте публичный проброс порта. Для реального сервера применяются отдельные учётные записи, секреты и проверка сертификата; настройка `TrustServerCertificate=True` здесь нужна для сертификата контейнера.

## Часть 5 Сохранение работы и завершение занятия

### Сохраните код в GitHub

Через панель **Source Control** просмотрите изменения, введите сообщение коммита, например `Practice 03 parameters and CRUD`, сделайте **Commit**, затем **Push** или **Sync Changes**.

То же через терминал, если сохранению подлежат все текущие изменения:

```bash
git status
git add .
git commit -m "Complete ADO.NET practice"
git push
```

Перед `git add .` проверьте список файлов. В репозиторий сохраняются код, SQL-скрипты и при необходимости отчёт с результатами. Файлы сборки и резервные копии баз исключены через `.gitignore`.

### Остановите окружение

1. Откройте [список своих Codespaces](https://github.com/codespaces).
2. Найдите нужную среду.
3. В её меню выберите **Stop codespace**.

Простое закрытие вкладки не означает остановку. Остановленное окружение не расходует вычислительное время, но продолжает занимать хранилище. Перед удалением сохраните всё нужное в GitHub или скачайте отдельно. [Жизненный цикл Codespaces](https://docs.github.com/en/codespaces/about-codespaces/understanding-the-codespace-lifecycle).

### Что происходит с базой

База хранится в Docker volume `sql-data`, привязанном к этому Codespace. Обычная остановка и повторный запуск сохраняют её. Удаление Codespace удаляет его данные; коммит исходников не является резервной копией SQL Server.

Для учебных работ сохраняйте SQL-скрипты создания и изменения данных, чтобы воспроизвести результат в новой среде. Если важны именно текущие данные базы, отдельно подготовьте экспорт или резервную копию и скачайте её до удаления Codespace.

Для следующего занятия откройте существующую среду из списка Codespaces. Не создавайте новую без необходимости.

## Часть 6 Настройки экономии

1. Используйте один Codespace на студента для этой дисциплины.
2. Начинайте с машины с 2 ядрами.
3. В личных **Settings → Codespaces → Default idle timeout** установите 10–15 минут для новых сред.
4. Всё равно останавливайте среду вручную в конце занятия.
5. Проверяйте расход в разделе оплаты и использования аккаунта, относящемся к Codespaces.
6. После сохранения результатов удаляйте ненужные среды: их хранение продолжает расходовать квоту.

Тайм-аут прекращает работу после отсутствия активности, а не по окончании учебной пары. [Настройка тайм-аута](https://docs.github.com/en/codespaces/setting-your-user-preferences/setting-your-timeout-period-for-github-codespaces).

## Часть 7 Если что то не запускается

| Проблема | Что сделать |
| --- | --- |
| Не найдена конфигурация | Проверьте путь `.devcontainer/devcontainer.json` в корне выбранной ветки |
| Неизвестна команда `dotnet` | Убедитесь, что создана среда с конфигурацией проекта; при её исправлении используйте Rebuild Container |
| SQL Server ещё не готов | Дождитесь завершения подготовки, затем повторите проверку |
| Создание остановилось на unhealthy database | Откройте creation logs, проверьте запуск сервиса `db` и его healthcheck; при нехватке памяти попробуйте 4 ядра |
| Сервер `(localdb)` не найден | Уберите строку LocalDB из примера и используйте `LabDb.ConnectionString` |
| Ошибка Windows-аутентификации | Здесь используется SQL Login, а не `Integrated Security=True` |
| Ошибка сертификата при подключении расширения | Для этого контейнера включите Trust server certificate |
| Не задан `MSSQL_SA_PASSWORD` | Переменная приходит из Compose; пересоздайте терминал или исправьте конфигурацию и выполните Rebuild Container |
| База или таблица не найдена | С исходным Program.cs выполните `dotnet run --project practice -- init` |
| Таблица уже существует | Не запускайте повторно исходные CREATE TABLE из лекций 2 и 4; используйте подготовленную базу |
| `Program` содержит несколько файлов с top-level statements | Оставьте один Program.cs; сохранённые копии перенесите или переименуйте в .txt |
| Команда `init` пропала | Вы заменили Program.cs примером из лекции; восстановите запускатель или используйте MSSQL |
| Codespaces не создаётся после исчерпания квоты | Проверьте отдельно вычисления и хранение; без оплаты дождитесь обновления квоты |

В контейнере приложения не установлен Docker CLI. Для диагностики создания используйте логи Codespaces, а для уже работающего приложения — запросы MSSQL или команды C#; команда `docker ps` внутри его терминала не нужна.

Пароль сервера устанавливается при первичной инициализации volume. Простое изменение значения в Compose не меняет пароль уже существующей базы. Для текущего учебного набора оставьте демонстрационный пароль; изменение действующих учётных данных — отдельная операция.
