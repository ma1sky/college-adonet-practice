# Настройка SQL Server и ADO.NET в Codespaces

В репозитории два отдельных проекта:

- `practice` — короткая программа студента: подключение, запрос и вывод имён.
- `setup` — подготовка базы преподавателем, автоматически выполняется при создании Codespace.

Студент работает в `practice/Program.cs` и запускает одну команду:

```bash
dotnet run --project practice
```

Установки на компьютер не нужны. В облачной среде работают .NET 10, SQL Server 2022 Developer
и провайдер ADO.NET `Microsoft.Data.SqlClient 7.1.0`.

## Преподавателю перед первым занятием

### 1 Проверьте репозиторий

В корне должны находиться `.devcontainer`, `practice`, `setup` и `sql`.
Файл `.devcontainer/devcontainer.json` задаёт конфигурацию Codespaces.
Docker Compose запускает приложение и SQL Server в одной облачной среде.
[Устройство dev containers](https://docs.github.com/en/codespaces/setting-up-your-project-for-codespaces/adding-a-dev-container-configuration/introduction-to-dev-containers).

Для первого запуска SQL Server в конфигурации переданы `ACCEPT_EULA=Y` и `MSSQL_PID=Developer`.
Ознакомьтесь с условиями лицензии перед использованием учебного окружения.
[SQL Server в контейнере](https://learn.microsoft.com/en-us/sql/linux/install-upgrade/quickstart-install-docker?view=sql-server-ver17).

### 2 Подготовьте копирование студентами

Откройте **Settings → General** и включите **Template repository**.
Тогда студент нажмёт **Use this template → Create a new repository** и создаст свою копию.
Если шаблон пока не включён, можно использовать **Fork**.
[Копирование шаблона](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template).

Студент должен создавать репозиторий и Codespace под своим личным аккаунтом.
Каждая среда содержит свою учебную базу; изменения одного студента не затрагивают остальных.

### 3 Проверьте Codespaces

1. Откройте **Code → Codespaces → New with options**.
2. Выберите ветку `main`, конфигурацию **ADO.NET and SQL Server practice** и машину с **2 ядрами**.
3. Создайте окружение и дождитесь окончания подготовки.
4. В журнале подготовки должно появиться сообщение `База CollegeAdo готова`.
5. Откройте **Terminal → New Terminal** и выполните `dotnet run --project practice` из корня репозитория.

На новой базе результат:

```text
Анна Иванова — ИСП-21
Борис Петров — ИСП-21
Вера Соколова — ИСП-22
```

Если 2 ядер для конкретного окружения не хватает, проверьте запуск на 4 ядрах,
учитывая более быстрый расход бесплатной квоты.
[Создание Codespace](https://docs.github.com/en/codespaces/developing-in-a-codespace/creating-a-codespace-for-a-repository).

### 4 Выдайте первую практику

Отправьте студентам ссылку на репозиторий и файл [ПЕРВАЯ ПРАКТИКА.md](ПЕРВАЯ%20ПРАКТИКА.md).
Для первого занятия достаточно чтения списка, изменения оформления, отбора группы и подсчёта.
Техническую подготовку из `setup`, регулярные выражения и разбор файлов изучать не требуется.

## Студенту

### 1 Создайте свою копию

1. Войдите в GitHub и откройте репозиторий преподавателя.
2. Нажмите **Use this template → Create a new repository** либо **Fork**.
3. Владельцем выберите свой аккаунт, задайте имя, например `adonet-ivanov`.
4. Перейдите в созданную копию: в адресе должен быть ваш логин.

### 2 Запустите окружение

1. В своей копии откройте **Code → Codespaces**.
2. Создайте окружение с **2 ядрами** и дождитесь окончания подготовки.
3. Откройте терминал и выполните:

```bash
dotnet run --project practice
```

Должны появиться имена студентов. Откройте `practice/Program.cs` и выполняйте задания
из [первой практики](ПЕРВАЯ%20ПРАКТИКА.md), меняя по одной строке и повторяя ту же команду запуска.
Команды с дополнительными аргументами `list`, `count` или `sql` больше не используются.

### 3 Сохраните результат

В панели **Source Control** проверьте изменения, выполните **Commit**, затем **Push** или **Sync Changes**.
Передайте преподавателю ссылку на свою работу. Для приватного репозитория предоставьте ему доступ.

### 4 Остановите окружение

В [списке Codespaces](https://github.com/codespaces) найдите свою среду и выберите **Stop codespace**.
Закрытие вкладки само по себе не останавливает машину.
На следующем занятии откройте существующий Codespace, вместо создания ещё одного.
[Остановка и сохранение работы](https://docs.github.com/en/codespaces/about-codespaces/understanding-the-codespace-lifecycle).

## Бесплатный аккаунт

Для личного GitHub Free на дату проверки 9 ноября 2026 года включены 120 ядро-часов
вычислений и 15 ГБ·месяц хранения. На машине с 2 ядрами предел по вычислениям — около
60 часов работы в месяц, с 4 ядрами — 30 часов.

Хранение учитывается отдельно: образы контейнеров, база и файлы занимают место.
Поэтому квота хранения может закончиться раньше вычислений. При отсутствии способа
оплаты использование блокируется после исчерпания квоты. Если карта привязана,
проверьте настройки бюджетов отдельно.
[Лимиты Codespaces](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces).

Для экономии используйте одну среду на дисциплину, останавливайте её после занятия
и удаляйте ненужные среды после сохранения работ. В **Settings → Codespaces → Default idle timeout**
можно установить 10–15 минут для новых окружений.

## Если Codespace создан до упрощения проекта

1. Сначала сохраните свою работу через Commit и Push. Если Git сообщает о конфликте,
   не перезаписывайте свой Program.cs: преподаватель должен помочь совместить изменения.
2. В копии-шаблоне изменения преподавателя автоматически не появляются. В fork можно
   использовать **Sync fork**; для отдельной копии по шаблону добавьте новые файлы из актуального
   репозитория или создайте новую копию, сохранив прежнюю работу.
3. В обновлённой локальной копии репозитория выполните `git pull` при отсутствии конфликтов.
4. Из корня обновлённого проекта выполните:

```bash
dotnet run --project setup
dotnet run --project practice
```

Для существующего окружения с теми же контейнерами достаточно этих команд.
При изменении самой конфигурации используйте **Codespaces: Rebuild Container**.

## Повторная подготовка базы

Преподаватель может выполнить:

```bash
dotnet run --project setup
```

Команда создаёт отсутствующую базу и таблицы. Студенты добавляются только при первом
создании таблицы `Students`: повторный запуск не удаляет данные, не добавляет копии
исходных записей и не возвращает изменённые группы.

`setup` сначала создаёт базу через отдельную SQL-команду, затем выполняет файл с таблицами
одной командой. В `sql/01-init.sql` нет `GO` и регулярных выражений для его поиска не требуется.
Этот служебный проект работает независимо от того, что студент написал в `practice/Program.cs`.

## Просмотр таблиц через MSSQL

Расширение MSSQL устанавливается в окружение автоматически.
Откройте палитру **F1 → MS SQL: Add Connection** и укажите:

| Поле | Значение |
| --- | --- |
| Server | `db,1433` |
| Authentication | SQL Login |
| User | `sa` |
| Password | `College_Lab_2026!Only` |
| Database | `CollegeAdo` |
| Encrypt | Включено |
| Trust server certificate | Включено для учебного контейнера |

Откройте `sql/02-check.sql` и выполните его через **Execute Query**.
[Подключения в MSSQL](https://learn.microsoft.com/en-us/sql/tools/visual-studio-code-extensions/mssql/mssql-database-connections?view=sql-server-ver17).

Пароль демонстрационный, только для изолированной учебной базы. Не публикуйте порт 1433
наружу и не загружайте в эту среду реальные данные. Изменение пароля в Compose не меняет
пароль уже созданного SQL Server — для начальной практики оставьте настройки без изменений.

## Как использовать четыре лекции

Сначала выполните упрощённую практику, затем переходите к материалам папки `lectures`.
Чтобы запустить полный пример из лекции, замените им **весь** `practice/Program.cs`,
оставьте `LabDb.cs` и используйте:

```csharp
string connectionString = LabDb.ConnectionString;
```

Запуск остаётся тем же: `dotnet run --project practice`.
Вторую копию программы не сохраняйте рядом с расширением `.cs`: используйте `.txt`
или отдельную папку вне `practice`, чтобы не создавать два файла с top-level statements.

База и обе таблицы уже созданы. Повторно выполнять `CREATE DATABASE` из лекции 2
и `CREATE TABLE` из лекции 4 не нужно.

## Данные и частые ошибки

База хранится в Docker volume `sql-data`. При остановке и запуске она сохраняется,
при удалении Codespace теряется. Коммит кода не сохраняет содержимое базы:
сохраняйте SQL-скрипты, а важные данные экспортируйте отдельно до удаления среды.

| Проблема | Что проверить |
| --- | --- |
| База не найдена | Дождитесь подготовки или выполните `dotnet run --project setup` |
| Таблица уже существует | Не повторяйте исходные CREATE из лекций |
| Ошибка с LocalDB или Windows-аутентификацией | Используйте `LabDb.ConnectionString` |
| Не задан пароль окружения | Создайте среду с конфигурацией репозитория или выполните Rebuild Container |
| Два файла с top-level statements | Оставьте один Program.cs в проекте |
| После изменения запроса ошибка C# | Проверьте кавычки и точку с запятой; меняйте по одной строке |
| После изменения запроса ошибка SQL | Сравните названия таблицы и столбцов с примером |
| SQL Server не запускается | Откройте creation logs; проверьте, хватает ли ресурсов машине |
| Квота исчерпана | Проверьте отдельно вычисления и хранение в своём аккаунте |

В контейнере приложения Docker CLI не установлен. Для диагностики используйте
журнал создания Codespaces и расширение MSSQL.

Конфигурация проверена статически; запуск в реальном Codespace при подготовке
этой версии не выполнялся. Преподавателю нужно проверить первый запуск перед занятием.
